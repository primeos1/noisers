NOISERS FC — PROJECT ROADMAP
=============================
Vale 2 Zenith · Est. 2021
Last updated: 2026-09-22

STACK
-----
Web frontend   : React + TypeScript + Vite + Tailwind CSS v4 + React Router
Mobile app     : React Native (Expo)
Backend API    : Laravel (PHP), consumed by both web and mobile over REST/JSON
Database       : MySQL
Auth           : Laravel Sanctum (token-based, shared by web + mobile)
Repo layout    : /frontend (web), /backend (Laravel, not yet created),
                 /mobile (React Native, not yet created)

PHASE 3 — ADMIN DASHBOARD (FRONTEND, AGAINST MOCK DATA FIRST)
-----------------------------------------------------------------
Build the admin UI in /frontend under an authenticated /admin section,
wired to the same mock data layer initially, then swapped to the real
API in Phase 5. Suggested build order:

[ ] Auth flow — real login form behaviour, session handling, protected
    route wrapper for everything under /admin
[ ] Squad management — add/edit/remove players, positions, jersey
    numbers, contact details, active/inactive status
[ ] Disciplinary — log yellow/red cards per set/match, attach a fine
    amount per card type, track paid/unpaid status per player
[ ] Sets & matches — create a set/match (date, opponent, venue,
    competition), mark result, assign it to a season
[ ] Goals & assists — record scorers and assisters per match, feeds the
    stats band and player profile totals automatically
[ ] Team randomizer — pick a pool of available players and split them
    into balanced teams for training/practice sets (e.g. by position mix
    or simple shuffle), with a re-roll action
[ ] Admin dashboard home — season-at-a-glance: next fixture, outstanding
    fines, top scorer, recent cards


PHASE 4 — LARAVEL BACKEND
----------------------------
[ ] `composer create-project laravel/laravel backend`, connect to MySQL
[ ] Sanctum auth (token-based) — login endpoint, admin user seeding
[ ] Core models + migrations:
      - User (admin/committee accounts, roles)
      - Player (bio, position, jersey number, status)
      - Season
      - Fixture/Match (opponent, competition, venue, date, result)
      - Card (player, match, type, fine amount, paid status)
      - GoalEvent / AssistEvent (player, match, minute)
      - TrainingSession / RandomizedTeam (for the team-randomizer feature)
[ ] REST API resource controllers + form request validation for each
    model above
[ ] Policies/gates so only committee/admin roles can write; public reads
    for fixtures/results/squad stay open (no auth) for the marketing site
[ ] API resource (JSON) shaping to match the TypeScript types already
    used in src/lib/clubData.ts, so the frontend swap is mechanical
[ ] Seed data + factories for local development


PHASE 5 — CONNECT FRONTEND TO THE REAL API
-----------------------------------------------
[ ] Replace src/lib/clubData.ts static exports with an API client
    (fetch/axios) hitting the Laravel backend
[ ] Add loading/empty/error states to every section that currently
    renders mock data directly
[ ] Real authentication against Sanctum from the /login page and the
    /admin section
[ ] Environment config for local (XAMPP) vs. production API URLs


PHASE 6 — MOBILE APP (REACT NATIVE)
----------------------------------------

PHASE 7 — POLISH & LAUNCH
------------------------------

[ ] Handover / short admin-user guide for the committee
